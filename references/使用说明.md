# 页面原型使用说明

页面原型让你在已登录的真实网页上分析逻辑、试改文案、样式和交互，并在 Chrome 中体验结果。预览只影响本机浏览器，不会发布到网站。

## 手动引用

在 Agent 的 Skill 选择器中选择 `page-prototype`，再输入需求。下文以 Codex 的 `$page-prototype` 为例；Claude Code 使用 `/page-prototype`，其他工具使用各自的显式引用入口。

```text
$page-prototype 如何使用这个 Skill？
```

这会显示使用说明，不会自动安装、启动或采集页面。每项新任务都先手动引用；同一项已发起任务中的补充说明、验收反馈和继续操作可直接接着说。

## 安装与首次接入

准备一台能运行本地 Agent 和 Chrome 的电脑。运行时要求 Node.js 20+、Chrome 125+；首次下载或更新还需 Git、npm 和访问 GitHub、npm 的网络。`npx skills` 有自己的 Node 版本要求，按其提示准备；当前工具在 macOS 验证。AI 需要能执行本机命令、读写文件和启动后台服务。

1. **安装 Skill**：在终端执行下面的命令，按提示选择使用的 Agent。

   ```sh
   npx skills add daxinbytes/page-prototype --skill page-prototype -g
   ```

2. **配置工具与第一个项目**：手动引用 Skill，告诉 AI 项目名称和目标网址。

   ```text
   $page-prototype 帮我配置页面原型工具，新增“演示项目”，入口是 https://app.example.test/app。
   ```

   AI 检查环境、自动获取运行时并安装依赖，创建项目后启动服务。已经安装时会复用本机工具。无需再手动下载第二份 Skill。

3. **加载扩展**：AI 会给出扩展目录的绝对路径。在 Chrome 打开 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择该目录。
4. **连接服务**：按 AI 给出的本机终端命令查看配对码，填到扩展的“配对码”输入框，点击“连接服务”。配对码只在本机使用，不发到聊天。
5. **接入页面**：打开并登录目标网页，在扩展中授权项目站点、选择页面并点击“开始项目协作”。看到页面跟随记录和资源数量后，可以开始分析或修改。

以后继续已有项目通常不必重复安装、加载扩展或配对。具体安装故障和更新步骤见 [接入与更新](接入与更新.md)。

## 项目与迭代方案

**项目**对应一套业务网站，可以包含多个已授权域名和页面。**方案**对应该项目的一轮原型修改，例如“第一轮搜索调整”“第二轮详情调整”。同项目新增迭代版本就是新建方案；扩展中的称呼是“方案”。

| 想做的事 | 可以这样说 | 会发生什么 |
| --- | --- | --- |
| 新增另一个项目 | `$page-prototype 新增“管理后台”项目，入口是 https://admin.example.test/。` | 创建独立项目配置。当前有其他项目协作时，先结束并切换服务，再接入新项目。 |
| 继续已有项目 | `$page-prototype 继续“演示项目”的“第一轮搜索调整”。` | 找到已有项目和方案，按需启动服务、重新接入页面；保留原草稿。 |
| 分析页面逻辑 | `$page-prototype 分析当前页面的搜索逻辑，说明调用哪个接口、使用哪些字段。` | 采集并读取代码、给出证据，不修改页面。 |
| 制作预览 | `$page-prototype 把当前页面的搜索按钮改成蓝色，并应用到页面。` | 在当前方案里制作修改，绑定目标页并应用，然后验收效果。 |
| 在当前方案上继续修改 | `$page-prototype 继续当前方案，把搜索按钮文案改成“立即搜索”。` | 累积修改同一份方案，不会新建独立版本。 |
| 同项目开始新一轮迭代 | `$page-prototype 在“演示项目”中，基于原始页面新建“第二轮搜索调整”，保留第一轮方案。` | 新建独立方案，从网站原始页面开始，旧方案与草稿保留。 |
| 查看已有方案 | `$page-prototype 列出当前项目的方案，告诉我正在使用哪一个。` | 显示方案名称及当前方案。 |
| 重命名方案 | `$page-prototype 把“方案 1”重命名为“第一轮搜索调整”。` | 保留方案内容，仅更改名称。 |
| 回到历史方案预览 | `$page-prototype 切换到“第一轮搜索调整”，并应用到当前列表页。` | 切换方案、核对目标页后应用原草稿；资源已更新时会提示重新适配。 |
| 恢复网站原貌 | `$page-prototype 停用修改并恢复当前页面。` | 停止覆盖并刷新恢复页面，草稿继续保留。 |
| 结束本次协作 | `$page-prototype 结束本次项目协作。` | 解除页面跟随并恢复仍在覆盖的页面，项目资料和方案保留。 |

### 新迭代与继续修改的区别

新建方案从**当前网站的原始资源**开始，不继承上一方案的修改；旧方案不会被覆盖。同一项目不必重新配置域名或加载扩展。

如果你希望保留当前调整继续完善，就说“继续当前方案”。这仍是在原方案上修改。当前没有一键复制旧方案创建独立分支的功能；需要“保留旧版，同时继承旧版做新版”时，请先说明这一点，让 AI 核对可行方法，不要把继续原稿误当成已保存新版本。

也可以在扩展中展开“基于原始页面 新建方案”，填写名称，点击“保留旧方案并新建”。新建、切换、应用及恢复可能刷新页面，先保存正在填写的表单。切换方案本身只恢复原页并载入草稿，需要点击“应用最新修改”或让 AI 应用后才看到效果。

## 页面跳转、跨域与新标签页

开始项目协作后，正常从列表进入详情或预览页即可。项目内导航和关联的新标签页会自动跟随，已授权站点内通常无需每页重新采集。

首次跳到新域名时，在扩展提示中加入并授权该站点，它仍可归属同一项目。独立打开、无法自动关联的标签页可在扩展中选择并接入。

描述修改时指出目标，例如“修改刚打开的详情页”。AI 会绑定明确页面，避免因切换浏览器标签而把修改应用到别处。

## 恢复、保存与再次使用

修改稿保存在本机方案目录中。关闭扩展面板不等于结束协作；“停用并恢复”与“结束项目协作”都会保留草稿。要从原始页面开始新的独立需求，使用“新建方案”。

下次手动引用 Skill，指定项目和方案即可继续。若网站已经发布新代码，原方案可能需要重新适配；旧稿不能保证直接套用。当前保存的是原型修改稿，不会自动生成开发需求文档或发布线上代码。

## 更新工具

更新 Skill 的说明和入口：

```sh
npx skills update page-prototype -g
```

更新本地服务和扩展时，手动引用并说：

```text
$page-prototype 帮我更新本地服务和浏览器扩展，保留现有项目和方案。
```

AI 会先结束协作、停止服务，再安装更新。随后在 `chrome://extensions` 重新加载扩展，再接入项目。配对信息和方案保留。Skill 更新与运行时更新是两个独立操作。
