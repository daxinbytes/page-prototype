# 修改与验收

## 选取目标与资源

从 `inspect` 读取跟随标签页的 ID 和完整地址。用户指向明确时直接使用；多个页面含义相同且无法确定时才询问。用目标页实际加载的资源 URL 选资源 ID，注意同一源码可以对应多个域名的资源。

确认当前方案后，运行 `stage --tab 标签页ID --scenario 方案ID 资源ID...`。命令返回绑定目标及 `overridePath`；只编辑这轮返回的修改稿。`originalPath` 是用于校验的原始基线。重新 stage 已有资源会保留此前草稿，先查看内容再继续。

提取出的 `.vue`、`.ts` 用于理解逻辑；直接改这些文件不会重新编译。当前预览修改的是浏览器实际执行的 JS/CSS。对于 webpack 的 eval 字符串，使用可靠的字符串解析与编码；定位替换时检查唯一性，保持 bundle 外壳和原有行为。无法可靠修改时说明原因，不用未经验证的大范围替换凑结果。

## 审阅并应用

用 `changes` 查看修改文件、原始哈希、修改哈希和差异摘要。摘要可能截断，需要时直接比较两条文件路径。确认修改范围对应用户请求。

运行 `apply --scenario 方案ID` 会刷新已绑定的目标页面。用户已授权预览且无未保存内容风险时可直接继续；若目标正在填写表单，先说明刷新影响。切换浏览器标签不会更改绑定；页面地址改变后，先核对用户意图，再用 `target 标签页ID` 显式重绑。

工具验证原始响应哈希、修改语法，并等待这一版所有选中资源的实际替换结果。`verified: true` 表示资源已替换，还需要验证文案、样式、点击、输入和原有交互中与需求有关的部分。具备浏览器操作能力时自行验证；仅用户能操作已登录浏览器时，给出简短验收步骤。

## 失败与恢复

- 资源版本变化：旧修改不会套用到新原始响应。读取新采集的资源，基于新版本重新制作修改。
- 目标跳转或关闭：先确认目标；不要默默把修改应用到另一个标签页。
- 部分资源失败或等待超时：查看 `status` 中目标标签页的 `outcomes`。若页面出现混合效果，先 `restore` 恢复，再处理失败原因。
- 连接中断：重新连接后确认项目和页面，必要时重新绑定；已经执行的修改代码需刷新才能恢复。

需要完全独立的新一轮时，回到主说明的“选择本轮修改方案”，创建新方案。

`restore` 停用修改并恢复目标页面，采集继续。`end` 结束所有页面跟随并恢复仍在覆盖的页面，保留磁盘资料。切换项目时依次 `end`、`stop`、`start 另一个项目`。

交付说明指出改了什么、应用到哪个页面、哪些行为已验证，以及恢复方法。浏览器预览不会改动站点的线上部署。
