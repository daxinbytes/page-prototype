# 接入与更新

## 首次接入

| 条件 | 要求与处理 |
| --- | --- |
| Node.js | 运行时最低 20；使用 `npx skills` 安装 Skill 时还需满足该 CLI 自己的 Node 要求，建议使用受支持的 LTS 版本。先检查 `node --version`。命令不存在时区分未安装与 Agent 的 PATH 不可见。 |
| Git、npm | 首次获取运行时和主动更新时需要。检查 `git --version`、`npm --version`；网络需能访问 GitHub 与 npm registry。依赖由 setup 自动安装。 |
| 执行环境 | Agent 能在 Chrome 所在电脑运行本地命令、后台服务并读写文件；可监听回环地址 `127.0.0.1`。默认端口 17373，冲突时识别占用进程或通过 `start --port 端口` 使用另一个服务端口。 |
| Chrome | 最低 125。首次加载扩展需要开启开发者模式，登录目标网站，并授权项目站点。 |

不需要数据库、Docker、Python 或单独的模型 API Key；模型能力来自用户使用的 Agent。网站所需的公司网络或 VPN 仍需正常可用。当前已在 macOS 验证，其他系统尚未实际验收。

1. 运行 `node '<Skill目录>/scripts/setup.mjs'`。缺少运行时会从配置仓库获取源码，执行 `npm ci --omit=dev --ignore-scripts`，安装到用户数据目录。临时下载副本随后清理，不保留第二份 Skill。
2. 将输出中的 `extension` 绝对路径交给用户。引导其在 `chrome://extensions` 开启开发者模式，点击“加载已解压的扩展程序”，选择该目录。
3. 用 `tool.mjs doctor`、`projects` 核对状态，执行 `start` 启动服务。项目可在扩展中选择或新建；用户明确要求 AI 新建时再执行 `init`。
4. 用户在本机终端通过 `tool.mjs pair` 查看配对码，在扩展中连接本地服务；先选项目，再打开目标页，点击“接入并开始协作”并授权站点。配对码不经过聊天。
5. `inspect` 显示目标页面与采集资源后，再按任务分析或修改。

环境能力、网络或权限不足时说明具体失败步骤，不声称已经安装或连接。首次启动和 Chrome 加载是两件事；脚本完成不代表浏览器已经接入。

## 目录与版本

全新安装默认 `~/.page-prototype`；发现旧 `~/.beta-preview/installation.json` 时沿用原目录。`installation.json` 记录工具、数据和扩展路径，`setup.json` 记录获取来源及实际 Git commit。

`PAGE_PROTOTYPE_HOME` 可指定自定义目录，兼容旧 `BETA_PREVIEW_HOME`。如果 setup 使用 `--home`，后续工具也要设置相同的 `PAGE_PROTOTYPE_HOME`。保持 Chrome 加载的稳定 `extension` 目录，不加载 `versions/版本号/extension`。

Skill 所需接口和最低运行时版本在 `runtime-source.json` 定义。当前从配置的分支获取并记录 commit，不会每次使用自动追踪最新代码。未来可以将 `ref` 改成已发布的 tag。

## 更新

用户要求更新时再执行相应流程：

- **更新 Skill**：通过安装 Skill 的 CLI 更新，例如 `npx skills update page-prototype -g`。这只更新 Skill 的说明和入口脚本。
- **更新运行时与扩展**：先结束网页协作并停止本地服务，再运行 `node '<Skill目录>/scripts/setup.mjs' --update`。安装器保留运行数据、方案、配对码和扩展路径，同版本不同内容会备份旧文件。0.8 增加读取标签页标题和地址的权限，Chrome 若提示新增权限需用户确认。完成后请用户在 `chrome://extensions` 点击扩展“重新加载”，然后启动服务并连接，在面板选择项目、接入页面。

若更新后的 Skill 拒绝旧版运行时，先读取原 `installation.json`，使用其中的 `tool` 路径执行 `end`、`stop`（设置对应 `BRIDGE_RUNTIME_DIR`），再运行 setup 的更新命令。服务已经停止时无需重复停止；不终止未知进程。

运行时仍在运行时安装器会拒绝替换。网络或安装失败时保留已有数据，核对错误后再处理。更新失败不要删除用户数据目录重装。

## 开发或手动获取

已有本地运行时源码时，可运行 `setup.mjs --source '<运行时仓库绝对目录>'`；已有安装需替换时加 `--update`。此方式仍需要 npm 下载依赖；只在来源明确时使用。

也可以直接在运行时仓库执行 `npm ci --omit=dev --ignore-scripts` 和 `node install.mjs`。Skill 根据安装记录找到工具，不要求两个仓库放在相邻目录。仓库根目录包含本 Skill，运行时仓库只包含服务与扩展。
